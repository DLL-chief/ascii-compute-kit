# 001. GitHub + GitHub Pages — единственный источник истины

* Статус: принято
* Дата: 2026-09-14

## Контекст

Эталонный шаблон vibecoders упоминает GitLab CI. У владельца рабочий аккаунт и уже существующие публичные демо — на GitHub (govnosert, acoustic-chronograph). Нужен статический хостинг без сервера. Проект учебный/шаблонный, команда — один человек.

Альтернативы: GitLab Pages, Cloudflare Pages, Netlify. Они дали бы кастомные заголовки (COOP/COEP) и SharedArrayBuffer. Для ASCII-art это не нужно.

## Решение

* Канонический репозиторий: `https://github.com/DLL-chief/ascii-compute-kit`.
* Публикация демо — GitHub Pages с этого репозитория.
* CI, если появится, — GitHub Actions, не GitLab CI.
* Зеркала и второй хостинг не заводим, пока Pages не упрётся в лимит (кастомные заголовки, размер артефакта).

## Последствия

Плюсы: один аккаунт, привычный Pages, относительные пути как в других репозиториях владельца.

Минусы: нет COOP/COEP → нет SAB и wasm-потоков. Это осознанно и записано в README / контрактах.

Отклонённые варианты: отдельный backend, сборка на Vite «сразу», GitLab «потому что так в шаблоне».

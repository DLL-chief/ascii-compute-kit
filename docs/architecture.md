# Архитектура ascii-compute-kit

## Назначение

Статическое веб-приложение в браузере. Пользователь видит исходную растровую картинку и её ASCII-представление. Система сама определяет, какие вычислительные контуры доступны, и гоняет один и тот же фильтр по выбранному бэкенду.

Нет сервера. Нет аккаунтов. Состояние не хранится дальше сессии вкладки.

## Компоненты (логические, код появится позже)

```
[index.html / UI]
        |
        v
   detect  ----флагидоступности---->  pipeline
                                                 |
                    +----------------------------+-----------------------------+
                    |                            |                             |
              backend-js                    backend-worker                backend-gpu
              (main thread)                 (JS и/или Wasm)               (WebGPU / WebGL2)
                                                 |
                                            ascii-kernel
```

* `detect` — одноразовый опрос среды: Workers, Wasm, WebGPU adapter, WebGL2, `crossOriginIsolated`.
* `pipeline` — оркестратор. Берёт RGBA, вызывает один backend, отдаёт RGBA или готовую сетку глифов в UI.
* `backends` — адаптеры с одним контрактом (см. `api_contracts.md`).
* `ascii` — сам алгоритм: нарезка на ячейки, яркость, индекс в рампе символов, растеризация глифов в bitmap.

## Поток данных

1. Источник кадра: сгенерированный тест 512×512 (градиент + несколько фигур) или, позже, файл пользователя.
2. `ImageData` / `Uint8ClampedArray` RGBA, row-major, 4 байта на пиксель, без преумноженной альфы.
3. Backend считает ASCII и возвращает либо:
   * растр того же размера (глифы уже нарисованы), либо
   * компактную сетку индексов символов + средний цвет, которую UI рисует через атлас.
4. На первой итерации канонический выход — растр RGBA того же `w×h`, чтобы UI был тупым: `putImageData`.

## Границы ответственности

| Слой | Можно | Нельзя |
| --- | --- | --- |
| UI | кнопки бэкенда, два canvas, строка детекта и тайминга | считать яркость пикселей |
| detect | feature detect | запускать фильтр |
| pipeline | выбрать backend, замерить время, поймать ошибку и откатиться | знать рамп символов |
| backend | говорить с Worker/GPU/Wasm | лезть в DOM |
| ascii-kernel | яркость → символ → пиксели глифа | знать, WebGPU это или JS |

## Деградация

Порядок предпочтения, если пользователь нажал «авто»:

1. WebGPU compute, если `navigator.gpu.requestAdapter()` успешен.
2. WebGL2 fragment, если есть `webgl2`.
3. Worker + Wasm, если есть и Worker, и Wasm.
4. Worker + JS.
5. JS в главном потоке.

Любой шаг может быть выключен вручную. Недоступный шаг в UI серый и подписан причиной из `detect`.
